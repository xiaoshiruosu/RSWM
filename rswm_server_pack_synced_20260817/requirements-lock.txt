# =============================================================================
# requirements-lock.txt —— RSWM-Bench 正式实验环境（GPU 训练 / 评估栈）
#
# 为什么单独建这个文件：`lora_remotesense/new/requirements.txt` 里真正的版本
# 钉死（torch 2.4.0 / torchvision 0.19.0 / cu121 / flash-attn 2.7.3）写在
# **注释**里，pip 读不到；文件正文全是 `>=` 下界。于是"照着 requirements.txt
# 装"和"照着注释装"会得到两套不同的环境，而论文数字只在后者上跑过。
# 本文件把注释里的口径搬进机器可读的位置。
#
# 口径边界（重要，别混）：
#   * 本文件 = **复现论文数字**的环境（Python 3.10 + CUDA 12.1 + GPU）。
#   * CI 的依赖不在这里，见 `.github/workflows/ci.yml`：纯 CPU、无 HF 网络、
#     只装跑单测与 `--no-hf` 建库所需的最小集，且**故意不钉死**版本
#     （CI 的职责是抓仓库回归，不是复现数字；把 GPU 栈搬进 CI 只会让
#     CI 变慢且在 py3.12 上装不上 numpy<2）。
#
# 标注约定：
#   * 无标注的 `==`  ：仓库里有明确出处（见每行的 [src]）。
#   * `# 待实测确认` ：仓库只给了下界，服务器上实际装到的版本没有留档。
#                      跑通后请用 `pip freeze` 回填，把 `>=` 换成 `==`。
#
# 出处：
#   [A] lora_remotesense/new/setup_env.sh 顶部的 PY_VER / TORCH_VER / TV_VER /
#       TORCH_CUDA / FLASH_ATTN_VER
#   [B] lora_remotesense/new/requirements.txt 的文件头注释块
#   [C] server_run/README_RUN.md §0「机器要求」表
# =============================================================================
