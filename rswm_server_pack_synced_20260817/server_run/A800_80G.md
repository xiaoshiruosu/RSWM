# RSRoll / RSWM：共享 4×A800-SXM4-80GB 运行说明

本说明对应 2026-08-13 ICLR 代码基线的 A800 适配版。A800 配置不改变 33 帧任务、
数据划分、LoRA rank、学习率或评估协议；它只改变设备选择、注意力后端、显存调度、
DataLoader 和缓存路径。H200/Hopper 路径仍由 `h200_141g` profile 保留。

## 已验证的固定环境

训练环境必须先核实，不能为了“兼容”随意升级：

| 项目 | 固定值 |
| --- | --- |
| GPU | 4× NVIDIA A800-SXM4-80GB（单个训练进程默认只暴露其中 1 张） |
| Driver / nvidia-smi CUDA | 535.261.03 / 12.2 |
| Python | 3.10.20 |
| PyTorch / torchvision | 2.4.0+cu121 / 0.19.0+cu121 |
| flash-attn | 2.7.3 |
| HF 栈 | transformers 4.51.3、tokenizers 0.21.4、diffusers 0.39.0、accelerate 1.14.0、peft 0.19.1、huggingface_hub 0.36.2 |
| 数值库 | numpy 1.26.4 |

下载与训练环境必须分开。模型/数据下载只使用
`/nix/rsroll_25828/envs/hf311`（Python 3.11.15、huggingface_hub 0.35.3）；
`server_run/offline_prefetch.sh` 会核实这两个版本，且不会升级训练环境。

## A800 默认配置

- BF16；不启用 FP8，不默认启用 `torch.compile`。
- micro-batch 1，gradient accumulation 4，gradient checkpointing 开启。
- `OFFLOAD=auto`：仅当可见逻辑 GPU 同时满足总显存 ≥97000MiB、空闲显存
  ≥90000MiB 才解析为 0；A800-80GB 因容量不足自动解析为 1。
- 33 帧正式协议保持不变。
- T5/VAE 串行换入 GPU；两个 14B DiT 专家同一时刻只允许一个驻 GPU。
- CPU expert offload 使用 `torch.optim.AdamW`；LoRA 梯度和 optimizer state 随专家迁移。
- `num_workers=0`、无 prefetch/persistent workers，避免拥挤的 `/dev/shm`。
- `attention=auto`：A800(sm80)优先 FlashAttention-2；导入、ABI 或 kernel 失败时回退 SDPA。
- 缓存、临时文件、模型、日志和工作目录全部位于 `/nix/rsroll_25828`。

两份 14B BF16 专家仅权重就约 56GB；T5/VAE、LoRA 梯度/state、激活和临时 buffer
还会增加 CPU/GPU 占用。因此 A800 `auto` 不会选择两个专家同时常驻。用户仍可显式
`OFFLOAD=0` 做吞吐/OOM 边界测试，但在真实三级 GPU smoke 和 33 帧 smoke 通过前，
该配置不得进入正式矩阵，也不能预先宣称峰值或吞吐。

## 安全的第一条命令

由管理员确认一张空闲卡后，在服务器上执行；代码不会替你选卡，也不会改写
`CUDA_VISIBLE_DEVICES`：

```bash
cd /nix/rsroll_25828/<代码目录>/rswm_server_pack
export CUDA_VISIBLE_DEVICES=<管理员分配的单个物理卡号>
source server_run/a800_env.sh
python scripts/preflight_a800.py --strict --require-single-visible --min-free-gib 70
MIN_FREE_GIB=70 SMOKE_LEVEL=3 bash server_run/run_a800_smoke.sh
bash server_run/capture_a800_environment.sh
```

三级 smoke 分别检查：依赖/工程导入、CPU 上真实 PEFT LoRA 注入与前向、单张 A800 上
BF16 forward/backward/AdamW 和真实 RSWM 注意力入口。它不下载权重，也不启动正式训练。
`tests/test_a800_smoke.py --level 1|2|3` 是同一实现的标准测试入口；旧的
`server_run/a800_smoke.py` 入口继续保留，二者不会漂移。

若要做明确批准的 resident throughput 边界测试，必须单独目录运行：

```bash
OFFLOAD=0 bash lora_remotesense/new/run_train.sh
```

这不是 A800 的默认值，也不是 smoke 配置；OOM 只记录并停止，不降低 33 帧任务。

只有前三层通过且真实 checkpoint/HDF5 已准备好时，才可由用户显式请求一条 33 帧、
1 train + 1 val 样本的真实模型 smoke：

```bash
CUDA_VISIBLE_DEVICES=<单卡> CHECKPOINT_DIR=/nix/rsroll_25828/models/lingbot-world-base-cam \
DATA_PATH=/nix/rsroll_25828/<数据>.h5 MIN_FREE_GIB=70 REAL_MODEL_SMOKE=1 \
bash server_run/run_a800_smoke.sh
```

真实 smoke 的输出与正式实验必须分目录；`--max_train_samples=1` 和
`--max_val_samples=1` 会写入 manifest，不能进入论文主表。

## H200 与多卡边界

- Gadi/PBS 的 `_pbs_env.sh` 保持 `HARDWARE_PROFILE=auto`，不会被 A800 默认覆盖；
  H200 可显式使用 `h200_141g`，保留双专家常驻、FA3→FA2→SDPA 路径。
- 所有现存 PBS 文件的 `#PBS -q gpuhopper` 是旧集群队列名。A800 共享服务器优先用上面的
  直接单卡入口；若管理员要求 PBS，必须由管理员提供真实队列名，代码不猜测。
- A800 单专家 CPU offload 与经典 DDP 不兼容。当前 A800 正式默认仅支持单进程单卡；
  多卡只允许通过显式 launcher 发起，并会在加载 28B 权重前拒绝未验证的 offload+DDP
  组合。FSDP/model parallel 未经实测前不能声称支持。

任何 preflight/smoke 失败都应先修复环境或路径。不要清理 `/tmp`、`/dev/shm`，不要终止
其他用户进程，也不要因为代码能导入就把状态写成“实验成功”。
