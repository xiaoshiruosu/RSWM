# Baseline Fairness Report

## Fully comparable single-image track

Methods in this track must share one frozen manifest, one condition image, requested
trajectory, frame counts, evaluation code, seed protocol, and success-rate gate.

| Method | Native output | Trajectory input | Adaptation | Current evidence |
|---|---|---|---|---|
| Persistence | video-like constant rollout | ignored | repeat image | synthetic CPU smoke only |
| Generic outpainting | image | adapted from requested path | sequential translate/inpaint | adapter present; real checkpoint run NOT RUN |
| Frozen Wan/LingBot I2V | video | producer pose route | none; 0 adaptation params | standalone producer + ingest bridge; NOT RUN |
| Same backbone, no camera | video | camera route disabled | matched LoRA recipe | config/bridge present; NOT TRAINED |
| RS-Roll matched arms | video | native or dropped by declared arm | rank/target as config | configs/bridges present; NOT TRAINED |

Image methods must be labeled as adapted rollouts.  Their native output is a single
image and recursive error propagation is introduced by this benchmark bridge.

## Adapted direction-only image track

Remote Sensing-Oriented World Model / RemoteBAGEL is described by the paper as
direction-conditioned neighboring-image extrapolation.  No verified official runnable
code/checkpoint was found in the audit.  The local `rswise_recursive` remains a stub;
`rswise_recursive_bridge` accepts only a full T-frame product generated by an explicitly
documented recursive/per-waypoint producer.  It never presents that adaptation as an
original method capability.

## Diagnostic/upper-bound track

| Method | Privileged information | Allowed use |
|---|---|---|
| GT oracle | future GT rollout | metric ceiling only |
| Deterministic translation | full static scene + benchmark waypoints | oracle-like crop upper bound |
| Random-direction translation | full scene + benchmark motion scale | metric-discrimination diagnostic |

These rows must not be ranked against deployable methods.

## Separate multi-view track

MVSplat360 consumes multiple context views and camera poses.  RS-Roll's core task uses
one condition image plus a requested trajectory.  Because the input contracts differ,
MVSplat360 belongs in a capability table, supplementary material, or a separately named
multi-view track—not the fully comparable main table.

## Matched causal comparisons

The former `native_attn_cam_r16` vs `drop_attn_only_r16` comparison changed both pose
route and LoRA target modules.  It cannot establish a single-factor effect.  The added
2x2 matrix is:

| Pose route | attn_only r16 | attn_cam r16 |
|---|---:|---:|
| native | configured | configured |
| drop | configured | configured |

Data, split, training budget, batch, frame counts, evaluation manifest, and seeds are
identical in `configs/benchmark_ablation/`.

The rank sweep in `configs/rank_sweep/` fixes `native + attn_cam` and changes only rank
and the declared `alpha=rank` rule for `r={4,8,16,32,64}`.

## Failure and missing-metric policy

- Generation failure is explicit and non-zero unless `--skip-failed` is requested.
- A success-rate threshold gates any partial run.
- Failed samples never enter averages.
- Missing optional metrics are `null`, never zero.
- `result_available` is not enabled by adapter or synthetic-smoke success.
- No code/report claims that video diffusion outperforms image methods before formal
  results exist.
