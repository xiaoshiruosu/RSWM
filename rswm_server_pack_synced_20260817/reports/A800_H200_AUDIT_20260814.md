| `animate/face_blocks.py`、`s2v/auxi_blocks.py` 及镜像 | 绕开主调度器，直接调用 `flash_attn_func`，只捕获 `ImportError` | wheel ABI 的 `OSError` 或 kernel 错误直接崩 | 同步增加 `auto/flash_attn/sdpa` 行为与 SDPA 回退 |

Hopper-only Triton kernel 或自动 `--nproc_per_node=4` 需要迁移。TF32 开关在 Ampere 可用，
BF16 是 A800 正式默认。

## 5. A800 默认参数

| 参数 | 默认 | 原因 |
| --- | --- | --- |
| precision | BF16 | A800 sm80 原生支持；不依赖 FP8 |
| micro-batch | 1 | 避免同一 batch 同时命中 low/high 专家；80GB 稳定优先 |
| grad accumulation | 4 | 保持有效 batch，而不增加单步激活 |
| gradient checkpointing | 开 | 降低 33 帧 DiT activation 峰值 |
| offload | auto（A800 解析为 1） | 只有 total≥97000MiB 且 free≥90000MiB 才自动选择双专家常驻；显式 0/1 均保留 |
| attention | auto：FA2→SDPA | A800 优先已验证 FA2；ABI/kernel 失败可回退 |
| workers / prefetch / persistent | 0 / 无 / false | 避开已占满的 `/dev/shm` |
| pin memory | false | 降低共享节点锁页内存压力 |
| T5 / VAE | CPU，串行 GPU swap | 不与活动 14B 专家长期并存 |
| inactive expert | CPU | GPU 同时只驻一个 14B 专家 |
| optimizer | torch AdamW | 支持 state 随参数 CPU/GPU 迁移；禁用 offload+bnb |
| torch.compile | false | 避免首次编译峰值、Triton cache 与未验证图捕获 |
| FP8 | false | A800 正式路径不依赖 Hopper FP8 |
| frames | 33 | 保持论文任务，不通过减帧“解决”显存 |

`a800_80g` 会在加载 28B 权重前检查：只可见一张卡、名称含 A800、sm80、75–90GiB。
多卡或错误 GPU 会 fail-loud；代码不会自己选择、占满或杀掉其他 GPU 任务。

## 6. 显存与系统内存分析

- 单个 14B BF16 DiT 权重约 28GB；两个同时常驻约 56GB，尚未包含 activation、VAE/T5、
  CUDA workspace、LoRA gradient 和 Adam state，因此原 H200 resident-expert 路线对 80GB
  风险不可接受。
- A800 路径在 VAE/T5 运行前先卸载两个专家；完成 latent/context 后只换入当前 timestep
  使用的 low 或 high 专家。gradient accumulation 时，未活动专家的 LoRA gradient 与
  AdamW state 一并放 CPU，下一次使用前再换回。
- DataLoader 不使用 worker/prefetch；临时文件与所有 cache 在 `/nix/rsroll_25828`。
- 建议系统 RAM 至少 128GB，因为两个专家在批间可能同时位于 CPU，另有 T5/VAE、数据和
  checkpoint 序列化开销。该值是容量规划，不是本轮实测峰值。
- 仍需在真实服务器记录：FA2 与 SDPA 各自峰值、33 帧真实 batch 的 allocated/reserved、
  CPU RSS、swap 时间、VAE/T5 瞬时峰值、不同 rank/target 的 optimizer state。
