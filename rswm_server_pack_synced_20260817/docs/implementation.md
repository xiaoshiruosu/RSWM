# Implementation Guide — RS-Roll Fair Baseline Platform
> Generated: 2026-08-16 | Strategy: incremental extension | Status: IMPLEMENTED_CPU_VERIFIED

## 1. Baseline and scope

- Source baseline: `rsroll-bench-iclr-20260815-a800-whurs19-experiment-runner-safety-patched`.
- Extension: `rsroll-bench-iclr-20260816-baseline-extension`.
- Core Wan/LingBot Video DiT, Video VAE, attention, 3D RoPE, camera injection,
  Plücker rays, and trajectory construction are `[KEEP]`.
- New work is limited to adapters, cards, lifecycle state, benchmark manifests,
  evaluation, runner/exporter, experiment configs, tests, and reports.

## 2. Unified data flow

```text
frozen H5 + frozen split
  -> build_benchmark_manifest.py
  -> rsroll.benchmark_manifest/v2
  -> BaselineAdapter.prepare/generate/postprocess
  -> video [T,H,W,C] uint8 (adapter boundary also accepts [T,C,H,W])
  -> standardized run directory
  -> future-only evaluator (frames 1..T-1)
  -> aggregate_metrics.json + sample_metrics.jsonl
  -> export_paper_tables.py
```

The condition frame is retained for provenance and trajectory origin but is excluded
from future visual-quality scores.  Missing optional metrics are `null`, never zero.

## 3. Implemented components

### 3.1 Protocol and manifests

- `server_run/baselines/protocol.py`
  - validates video tensors, frozen manifest checksum/schema, separate condition and
    rollout resolutions, overlap curves, and nullable metrics;
  - derives empirical difficulty bins from the frozen manifest distribution.
- `server_run/baselines/build_benchmark_manifest.py`
  - records sample/source/split identity, condition and rollout checksums, trajectory,
    per-frame condition overlap, adjacent overlap, endpoint/mean/min overlap, and bins;
  - full H5 hashing and explicit per-frame trajectory are headline defaults.
- `server_run/baselines/check_dataset_leakage.py`
  - audits exact SHA/path collisions and dHash near-duplicate candidates across datasets.

### 3.2 Adapters and cards

- Existing diagnostic generators remain in the registry.
- `result_adapters.py` bridges explicit saved T-frame outputs for frozen I2V,
  no-camera, RSWISE recursive adaptation, and matched RS-Roll arms.
- A bridge never loads or modifies the upstream model and rejects missing, empty,
  single-image, wrong-length, malformed, seed-mismatched, or condition-contract-
  mismatched output.
- One immutable JSON card per registry method declares native I/O, view count, pose,
  future-GT use, training data, adaptation, and fairness track.

### 3.3 Runner and evaluation

- Root `run_baseline.py` forwards to `server_run/run_baseline.py`.
- The runner freezes the resolved manifest/config/card and writes standardized logs,
  sample metrics, aggregate metrics, and video indices.
- `server_run/evaluate_baseline_results.py` always computes paired CPU SSIM/PSNR on
  future frames. LPIPS, FID, R3D proxy, and I3D-FVD are explicit opt-ins; distribution
  metrics fail before model loading when fewer than 32 complete clips are present.
- Standard I3D-FVD requires a user-staged extractor asset and remains separate from
  the existing R3D-18 proxy.

### 3.4 Experiments and export

- `configs/benchmark_ablation/`: matched native/drop x attn_only/attn_cam rank-16 cells.
- `configs/rank_sweep/`: native + attn_cam with ranks 4/8/16/32/64 only.
- `server_run/iclr_experiment_matrix.json`: deduplicated runnable matrix plus an
  explicit blocked full-fine-tuning entry.
- `tools/export_paper_tables.py`: generates main, overlap, trajectory, rank, target,
  cross-dataset, and efficiency CSVs from standardized results only, after checking
  sample IDs, row counts, schemas, and manifest identity.

## 4. Result contract

Each run directory contains:

```text
manifest.json
config.json
baseline_card.json
sample_metrics.jsonl
aggregate_metrics.json
videos/index.json
logs/runner.log
logs/run_status.json
```

`aggregate_metrics.json` records method, dataset/split, N/T, overlap bin, visual
metrics, distinct `FVD_R3D_PROXY`/`FVD_I3D`, trajectory metrics, experiment identity,
and lifecycle availability.  No paper result is emitted without an actual frozen-run
artifact.

## 5. Verification gates

1. CPU/synthetic tests validate adapters, manifests, failure handling, future-only
   scoring, experiment semantics, and table export.
2. A real A800 smoke must load the checkpoint, attach LoRA, confirm trainable params,
   run forward/loss/backward/optimizer step, and record memory/dtype/loss.
3. Formal training/evaluation can start only after dataset checksums, split identity,
   checkpoint identity, and offline metric assets are frozen.

## 6. Current limits

- No formal checkpoint/result was generated by this work.
- RSWISE/RemoteBAGEL has no verified runnable official implementation/checkpoint in
  the audited local environment; only an explicit adaptation bridge is present.
- MVSplat360 is a separate multi-view track and its upstream model was not run.
- Real image-outpainting, frozen I2V, no-camera, matched LoRA, and I3D-FVD runs remain
  blocked on assets and the formal A800 environment.

  primary seeds, a deduplicated matched 2x2, optional all-target cells, and a
  deduplicated rank 4/8/16/32/64 sweep.
- Added `experiment_plan.json` plus a CPU-only strict validator/materializer. It uses

  enter the plan.

  future-only evaluation/table export. Execute modes require explicit environment

  camera/Pluecker route, trajectories, datasets, or metric code.
