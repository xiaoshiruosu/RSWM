# RSWM Benchmark论文写作蓝图与主张—证据清单

版本：benchmark-first-plan-v1；日期：2026-09-12。
配套：仓库根目录plan.md。来源编号[S1]–[S17]与plan.md一致。

本文件是写作与实验组织蓝图，不是已完成的论文或实验报告。当前项目材料没有完整论文正文；以下结果位置均需由真实实验填入，不能将示例数字或期望结论写进投稿稿件。

## 1. 论文应当讲的一条主线

“视觉连续、正确执行数值位移、保持此前公开内容”是不同性质。我们在固定俯视的静态遥感场景中，用精确二维几何把它们分开测量，并明确哪些性质可以由显式存储保证、哪些仍依赖生成模型。基准的价值由测量有效性、真实强基线的区分度和跨来源证据证明，而不是由某个自家方法的领先证明。

建议标题：RSWM-Bench: Auditing Numerical Spatial Control and Persistent Commitments in Remote-Sensing Generation。

不要用“全能遥感世界模型”“首次拥有长期空间记忆”“可准确预测未观测地物”等标题。Inria-120是核心实例，不等于全球遥感生成的全域代表。

## 3. 摘要：六句结构与禁止事项

第一句：说明遥感空间生成的局部输入、数值查询和持久内容要求。
第二句：说明视觉质量或最终重访相似度不足以区分控制、承诺保持和未知内容质量；近邻研究已有方向外推/回环/多维评价，不能说完全没有研究。
第三句：介绍RSWM-Bench与固定Inria-120核心，包括地域隔离、数值尺度配对、首次再入和共同前缀分支。
第四句：概括不可补写的首次台账、已知/历史/未知区分、独立测量验证与覆盖报告。
第五句：写真实模型实验发现，给具体效应、城市/来源范围和覆盖；结果尚未取得时保留占位。
第六句：写实际发布的代码、重建清单、适配器和结果产物，不写尚未公开的权重或影像。

中文占位稿：

> 给定单张局部遥感观测，空间生成系统不仅需要响应二维位置查询，还需要在再次进入已探索区域时保持此前公开的内容。外观连续或最终返回图像相似，并不足以同时证明这些性质。我们构建RSWM-Bench，以RSWM-Inria-120为核心，在固定俯视的静态连续影像上定义数值控制、严格尺度配对、首次再入和共同前缀分支任务。评价分别处理真实已知区域、不可补写的生成历史与未知区域，并以受控错误和独立地域验证测量的适用范围。在[实际模型/配置数]个真实系统及[实际来源/地域范围]上的实验显示[发现一与效应]、[发现二与覆盖/成本条件]。我们发布[实际发布产物]，以支持对空间生成行为的可复算分析。

使用条件：前三句中“构建”也必须在真实集合验收后使用；当前只可作为计划稿。禁止用单测数、合成world_id、Oracle图像数填第五句。禁止把feature-MMD改善直接写成真实道路或建筑正确率提高。

## 4. Introduction逐段写法

### 第1段：需求，不夸大应用

从“同一局部观测能否支持可查询、可返回的空间生成”切入。遥感提供连续的静态二维画布和精确对应，适合把生成行为分解为可检验性质。不要声称合理补全就是实际未观测灾区的真实地图，或能直接用于应急决策。

### 第2段：用反例建立评测缺口

展示三个反例：Copy可以看起来稳定但不移动；固定噪声地图可以按坐标保持一切但内容不合理；系统可以在首次重遇旧目标时重绘，最后返回时再恢复。每个反例只证明一种指标不充分，不声称现有全部基准都犯相同错误。

### 第3段：与近邻研究建立区别

RSWISE/RemoteBAGEL覆盖方向外推[S1]；MIND覆盖控制与记忆[S2]；LoopNav研究空间一致性[S3]；Genesis研究多尺度地图生成[S4]。本项目要证明的是固定数值单位、首次承诺和失败覆盖的额外测量价值，而不是重新宣布这些问题存在。

### 第4段：提出基准和范围

说明真实源世界→查询程序→受限输入→不可回写提交→分项测量。强调保留地图/缓存合法性，未知区域不以隐藏实景作为唯一像素答案，全自动评价不等于完整语义认证。

### 第5段：三项贡献

贡献一用“protocol/data artifact”表述；贡献二用“validated measurement and failure handling”表述；贡献三必须是已获得的“empirical findings”，不是“我们评测了很多模型”。初稿没有结果时用显式占位。

## 5. Related Work不能写成关键词列表

按三组组织：遥感空间生成；动作控制/回环/长期一致性；生成质量与测量有效性。每组先概括已有能力，再定位本项目的研究差异。对比表列：数据环境、查询单位、未知GT解释、历史参考、重入事件、执行协议、失败/覆盖、资源报告。未核查单元填“未核验”，不要用空叉贬低其他工作。

版本变化要记录。LoopNav等工作有后续版本，不能只依据旧摘要说它没有某指标。数值、图像分辨率和模型数量只在与比较问题相关时写入正文。

## 6. Task Definition与Benchmark Construction

顺序：

(1) 世界W、origin、q、固定视口、静态范围；(2) 允许输入和禁止信息；(3) 离线/online16；(4) F2/F3/F5/F7；(5) 已知/历史/未知；(6) 首次承诺和失败；(7) 地域角色与世界处理；(8) 查询/标签生成和规模。

公式至少包括：固定坐标归一化；K/P/N；first_event和reentry_event；F3的2倍关系；F7共同前缀锚。不能先展示一个架构再说这个基准专门适合它。

正文用一个128²目标示例解释“首次到B不等于像素首次出现”和“最后返回不等于首次再入”。例图必须标明是几何示意还是模型输出。核心与same-start配对扩展、第二来源分表，不能混报包数。

## 7. Evaluation与Metric Validation

对每个量写五件事：问题、参考、公式、计划/有效分母、解释限制。解释不适用与提交失败的不同，不把后者删除。

验证章应该回答：已知正确输入得什么分；受控错误如何改变分数；哪些变化应触发弃权；是否在独立影像成立；指标是否会被合法但无意义的解法满足。

建议把固定地图一致性命题放主文短段，证明放附录。失败敏感性界[c*e,c*e+1-c]仅为有界RGB误差的可能范围，不叫概率置信区间。说明缺失首次参考没有被修复。

质量测量用first-commit mosaic而不是反复采每帧未知条带；特征、权重、resize与世界采样均冻结。以真实—真实、噪声/平铺等对照验证，不自称“人类偏好一致”。项目坚持全自动，不需要为了模仿VBench加入人工逐图评分；同时也不能借用VBench的人工有效性结论为本指标背书[S5]。

## 8. Experiments应该是一组问题的回答

| 主文小节 | 关键比较 | 至少报告 | 可能结论及必要限制 |
|---|---|---|---|
| Numerical control | 无数值/数值，F2/F3 | 幅度误差、交叠、可信覆盖、完整率 | 有移动感不等于幅度控制；须真实消费数值 |
| Persistent commitments | 最终B/首次再入，F5/F7 | 各支锚、gap/调用、首次失败 | 终点可掩盖较早重写；需要真实系统例证 |
| Representation mechanisms | 同骨干历史策略与保护 | 质量、控制、保持、时间/内存 | 分析保证来自何处，不推断神经内部记忆 |
| Map generation order | Raster/Frontier/Lazy | 可见I0比例、窗口数、未知质量、成本 | 先排除弱整图策略造成的混杂 |
| Generalization | SFO/Innsbruck/外源 | 每域表现与覆盖、预训练信息 | 只在所测地域/来源范围内成立 |
| Reliability and utility | 缺失/参数/样本数，小改进 | 敏感性、复现、预注册方向 | 基准能揭示与指导问题；不保证所有指标同时改善 |

若所有真实方法在某个指标都饱和，报告它是约束校验而非有区分力的主排名；不要通过禁止地图或临时扩大范围制造优势。若运动测量大面积弃权，先改进仪器并重新验证，而不是只报少量可测图上的好分数。

## 9. 主张—证据表：写一句结论就填一行

| 主张草案 | 需要的原始证据 | 没有这些证据时应写 |
|---|---|---|
| 基准能区分控制与保持 | Copy/噪声/运动扰动＋多个真实模型 | 设计上区分，实际区分度待验证 |
| 首次再入更敏感 | 同轨迹同输出的终点/首次再入比较 | 它测不同事件，不能预断更强 |
| 增量地图更节省 | 同骨干Frontier整图完整初始化与总任务成本 | 当前仅实现按需机制，无性能结论 |
| 数值编码改善尺度响应 | 同训练预算/骨干、固定单位消融和coverage | 提出数值条件参考方案 |
| 泛化到新地域 | 每城与第二来源真实数据结果 | 仅在核心两城市或当前域有证据 |
| 基准可复现 | 独立环境源→世界→任务→评分重建 | 代码含演示/单测，完整复现待完成 |
| 自动评价可靠 | calibration锁定＋validation＋操作级真值 | 工程实现可运行，测量适用性未认证 |

不设硬性必须得到的效果值。效应不存在、区间宽或跨模型不一致本身可成为结果，但要判断是否足以支撑论文的研究价值。

## 11. CVPR / ICLR写作重心与投稿检查

CVPR路线建议强调真实视觉问题、几何可解释测量、视觉反例、强生成基线和可用资源。ICLR路线建议强调表示/状态机制、测量可识别性、输入条件与控制行为、跨骨干结论。两条路线都需要实际研究证据，不要求强行添加一个新网络。

截至2026-09-12，CVPR 2027注册11/10、正文11/16、补充11/23；ICLR 2027摘要9/18、正文9/25。ICLR当前正文初稿上限9页，要求AI use statement；匿名、作者资格/审稿责任和并行投稿按官方指南逐项检查[S15–S17]。日期不是论文完成证明，不把未完成的项目包装成已完成研究来赶截止。

提交前删除所有[待填]、TODO结果占位、内部路径、作者身份和无支持主张。校对表格计数：F7为160唯一新输出；核心1920包；同起点扩展不混入；测试两城市；未知区域不报唯一GT正确率。

最终判断：论文应让审稿人看到“为何需要这个benchmark、指标在哪里可信、强模型暴露了什么问题、别人能怎样复现或使用”。增加代码行数、测试数或视频数不能替代这四个回答。
