## 1. 项目是什么

RSWM-Bench 是一个以 Benchmark 为主的遥感空间生成研究项目。它将一幅连续遥感 RGB 图像视为有限静态世界 W，给模型一张真实初始观测 I0、二维数值空间查询与协议允许的历史，要求模型返回对应位置的 RGB 视图。

查询序列表示空间访问顺序，不表示真实时间。项目不直接评价现实未来事件、三维重建、真实卫星姿态或无限地图。

核心问题分为五个层面：

| 层面 | 要回答的问题 | 不应混同的结论 |
|---|---|---|
| 条件表示 | 原始数值指令是否被编码保留下来？ | 张量存在或哈希相等不证明网络执行正确 |
| 数值控制 | 图像中的内容位移是否响应方向、距离和尺度？ | 视觉上在移动不等于按数值控制 |
| 历史承诺 | 再次看到旧区域时是否保持此前首次公开内容？ | 两分支彼此相似不等于保持共同前缀 |
| 未知分布 | 新生成区域的分布特征在所用仪器下是否合理？ | 与隐藏未来不同不等于全部错误；分布相似不证明语义真值 |
| 成本与可靠性 | 为上述行为付出多少生成、状态、时间、显存及失败代价？ | RGB 画布大小不是完整状态；缺测不能写成零 |

旧相机条件 Wan/LingBot 与 LoRA 工作作为参考系统和机制实验加入，不再占据论文唯一主角。论文贡献来自**可复现任务、可信测量和公平跨范式实证分析**，不是要求自家方法在所有指标上第一。

### 1.1 不变的核心规格

- Benchmark：`rswm-inria-120-v0.1`。
- Inria 固定 revision：`ad8315c82c8a3021b93a7d52922d19ea76201f60`。
- 原始 RGB TIFF 5000×5000；中央 `[452:4548,452:4548]` 裁出 4096²；非重叠 2×2、uint16 求和、`(sum+2)//4` 得到 2048²。
- 世界名义 GSD 0.6 m/px；无损 PNG。不逐帧调色，不将 mask 或无关小图拼接成世界。
- 规范视口 H=240、W=416；四 origin 为 `(960,960),(1088,960),(960,1088),(1088,1088)`。
- q 相对任务 I0，x 右正、y 下正，两轴范围 `[-704,704]`；条件固定除以 `sqrt(416²+240²)`，在线调用之间不重设任务原点。
- 60 train、12 dev、12 metric_calibration、12 metric_validation、24 test；测试地域是 sfo 和 innsbruck，各 12 世界。
- 核心 120 世界、480 I0、1920 任务包。训练 3840 个 33 视图 clips、126720 个真实视图事件，索引按 batch 裁图。

| 任务 | 核心能力 | 每 origin 新输出 | 执行 |
|---|---|---:|---|
| F2 | 多段方向、距离、转弯 | 32 | offline |
| F3 | 同形严格两倍尺度响应 | 64 | small/large 分别 reset |
| F5 | 离开后的逐像素首次再入 | 96 | 6 次 online16 |
| F7 | 共同前缀后的双分支保持 | 160 | 32 前缀 + 64 + 64 |

F3 不是默认的未见尺度外推。F7 不是 192 个输出。相邻交叠下限 0.65 不因运动仪器的搜索参数而改变。所有具体离散参数、proposal 上限和标签仍调用冻结实现，不重新手写另一份生成器。

### 1.2 评价不能改变的语义

K 对 I0；P 对不可补写的首次公开输出；N 使用首次提交构建固定未知图块的分布评价。`first_event` 是第一次**计划**曝光，不是第一次成功生成。第一次缺失后，后续成功不能修复首次参考。

F5 在每像素第一次重新出现时评价；最终到达 B 是辅助结果。F7 两支分别锚定共同前缀，共同前缀成本与提交只计一次。

计划集合先于执行。正式主分析保持 `first_attempt_only`，恢复结果另表，所有 attempts 的实际成本保留。结构性不适用、缺失、不可测、输出失败与完整性失败分别记录。

## 4. Codex 持续工作的执行合同

### 4.1 持续推进，而不是每阶段都等待“继续”

在当前会话、已授予工具权限和预算内，只要有前置条件满足的必需工作，就继续执行。完成一个里程碑后核验证据、更新状态，直接进入下一可执行里程碑，不仅返回下一步建议。

持续执行依赖可执行环境；提示词不能创造未授予的服务器访问、真实权重、GPU 或无限运行额度。会话中断时按第 4.4 节接续，不声称仍在后台工作。不得通过递归调用代理、无限 shell 循环、跳过权限检查或无限增加重试来制造“永不停止”。

### 4.2 每个工作单元的循环

```text
读取既有目标/状态和实际 Git/进程
→ 找到依赖满足且尚未验收的必需工作
→ 判断是执行任务、修复缺陷，还是外部输入缺口
→ 在预算内实际执行；保存退出码、产物和失败现场
→ 按既有验收器核验
→ 代码变更则做定向回归/必要完整测试
→ 更新持久状态和证据路径
→ 继续下一单元
```

优先级：保护正在运行的工作和唯一原件 > 处理新出现的完整性风险 > 恢复真实输入 > 真实运行/正式测量 > 对明确缺陷的代码修改 > 文档同步。不能因为文档容易完成，就一直写文档。

### 4.3 遇到阻断怎么处理

先区分：

| 状态 | 处理 |
|---|---|
| CODE_FAILURE | 在范围内定位并修复，回归后继续 |
| INPUT_BLOCKED | 精确列缺失资产、路径或技术选择，继续不依赖它的任务 |
| ACCESS_BLOCKED | 记录实际错误及受限范围，不绕过授权 |
| BUDGET_BLOCKED | 保留已发生的全部成本，停止相关昂贵动作，申请具体差额 |
| RUNNING | 记录真实 PID/job/目录，观察已有进程，不重复启动 |
| DONE | 必須有范围匹配的证据；不能仅改状态字段 |

同一个缺失条件没有变化时，不重复同一资产扫描、HTTP 502 通道或同一个拒绝门。建议同一传输条件最多两次有界尝试，第二次应有诊断目的；新通道、新 locator 或权限变更才构成新的尝试条件。此规则是本计划建议的操作上限，不替代现有更严格的限制。

当全部剩余必需任务均被不可自行解决的外部条件阻断，允许暂停，输出**一张集中缺口表和恢复所需最小实值**。暂停不等于完成，也不需要为了交付再新增一层空代码。

### 4.4 跨会话接续

优先使用既有 `plan.md`、`docs/BUILD_STAGE_STATUS.md`、`evidence/implementation-status.json`。在既有状态中维护一个简短“当前执行游标”；仅当现有格式容不下才增加一个小型 Markdown 执行状态文件，不建设新任务数据库。

执行游标至少写：基线/HEAD、工作树改动、已核验等级、当前 M 项、最后成功命令、当前失败命令、输出目录、运行 PID/调度 job、预算已用/剩余、证据链接、输入缺口和下一条**真实可执行命令**。

计划结束前保存：尚未提交的用户/代理修改区分、实际进程状态、最后读取的上下文和不得重跑项目。下次先读取这些信息并核查进程，不能从头全量重跑。

完成阶段用 `DONE`；上下文或执行额度不足用 `HANDOFF_REQUIRED`；外部缺输入用对应 BLOCKED。后两者不能改成 COMPLETE。

### 4.5 有边界的自主决策

Codex 可在授权范围内自行完成模块定位、现有命令适配、依赖冲突修复、回归、源/权重清点、已批准下载、输出分析和开发分支提交，不为每个小操作询问。

下列事项不得自行决定：增加付费/算力/下载预算、变更冻结任务/样本/数据角色、使用未经决定的权重或数据、在看 test 后选模型/阈值、公开私人产物、删除唯一原件、合并 main 或正式发布。

技术方案缺省不应全部转嫁给用户：可以依据已经批准的候选和开发集提出**一套**带理由与成本估计的参数方案，集中等待批准。不得将未批准值写成 `approved=true`，也不得以 JSON 布尔值代替真实许可依据。

| 首次再入 vs 最终返回 | 同一实际F5/F7输出 | 两时点差异、gap/调用/覆盖 | 优先只重算，无需重生成 |
| 地图顺序 | 同completer的Raster/Frontier/Lazy | 上下文组成、质量/保持/成本 | 同配置已跑项可复用 |
| 历史与保护 | 既定LastFrame/FrameCache/Map及I0/历史保护 | 保持来源、质量和状态成本 | 缺机制状态支持才定向修改 |
| 同起点返回 | 现有same-start study，不改核心1920包 | exact/offset配对统计 | 使用独立study索引 |
| 独立来源 | 既定LEVIR100-LR64 | 原尺寸生成/再入、覆盖和资源独立表 | 复用通过审计的历史源像素 |

条件数值变换的bug修复不自动证明模型性能提升；显式地图的零保持误差不自动证明网络记忆。负结果和机制差异都可以成为真实研究发现，不事先规定赢家。

LEVIR只用image1、原1024²，不resize/pad到2048、不拿image2当未来帧、不与Inria混榜。先核对实际模型能否消费LR64的world spec；不兼容时只做受限接口适配和原核心回归，不伪造可用状态。

FAIR1M/OSCD仍是已有候选探针，不进入本次总目标关键路径，不再增加十个数据源延后主研究。其未验收大小、GSD、地理和许可条件不能当作已解决。

**验收：**上述已冻结必要study有真实结果、完整计划分母和替代解释分析；论文重要结论不只建立在一个未独立验证的实现上。若资源不足，需明确变更研究范围，原目标不能无声降级。
