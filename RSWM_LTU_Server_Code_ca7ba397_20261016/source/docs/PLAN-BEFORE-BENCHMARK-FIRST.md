## 1. 投稿定位与相关工作

### 1.1 推荐问题与可证伪假设〔研究建议〕

工作标题：**RSWM-Inria-120: Auditing Numerical Spatial Control and Persistent Commitments in Remote-Sensing Generation**。

H1：方向条件足以产生移动感，但不能保证固定单位下的幅度响应；F3 的严格 2 倍命令与独立图像运动测量可以识别该差异。

H2：最终 B 重访的一致性可能掩盖逐渐返回过程中的历史重写；逐像素首次再入比最后一次到达更直接对应跨调用首次重遇旧内容。

H3：显式坐标地图可以由表示机制保证部分一致性，但未知分布质量与生成成本并不随之获得保证。

H4：表示机制和测量覆盖的差异能否跨城市、跨来源复现，必须由独立实景实验检验。

上述均为待检验假设，不预设视频或地图获胜。核心贡献应是可执行协议、经过验证的测量、以及有外部复现支持的机制结论，而非仅增加任务名称。

## 3. 地域划分、源冻结与转换

### 3.1 固定配额

| 角色 | 城市/区域 | 每区源瓦片 | 总世界 |
|---|---|---:|---:|
| train | austin / chicago / vienna | 20 | 60 |
| dev | kitsap | 12 | 12 |
| metric_calibration | bellingham | 12 | 12 |
| metric_validation | bloomington | 12 | 12 |
| test_unseen_city | sfo / innsbruck | 12 | 24 |

源原始 split 与基准角色不是同一个概念。保持显式 city→source_split 检查，不因来源变更自动把某个城市塞入另一个角色。`sanfrancisco→sfo` 是唯一预置别名，其余名称差异必须人工审核并版本化，而不是模糊匹配。

### 3.2 正式冻结流程

用 HfApi 获取完整 commit SHA、全部文件路径、精确字节数及可获得 LFS SHA256；`files_metadata=True` 的接口定义以官方文档为准。[S04–S06] 保存完整 `inventory.json`，不能只保存最后选中的120行。

只接受正则 `data/(train|test)/images/([A-Za-z-]+)(\d+)\.tif`。按 `SHA256('rswm-inria-120-v0.1/' + path)` 排序，分城市取前 k 幅。冻结 `revision/source_split/path/city/role/rank/size/checksum/world_id`。构建产物内容不同必须换目录，不覆盖旧版。

当前 HF 网页可见每文件约75 MB、源测试图片目录约13.5 GB；这些是页面舍入显示，不是精确 source manifest。120文件约9GB只能用于临时下载预算，正式数字必须累加 API 字节数。本轮没有获得可验证的完整 revision，不将网页短 SHA 补写成40位值。[S04–S05]

`verify_manifest(manifest)` 现在会核对内部结构、角色配额、版本、路径、排序、ID和字节总计。`verify_manifest(manifest, inventory)` 还会核对该完整 inventory 的真正 top-k。**只有已选行时无法证明未选候选的排序；校验通过也不等于确认来源身份。**

建议在联网机器显式保存 inventory 后构造清单：

```python
from rswm_inria.data import freeze_metadata, select_manifest, verify_manifest, write_json
inventory = freeze_metadata()
manifest = select_manifest(inventory)
verify_manifest(manifest, inventory)
write_json('data/inventory.json', inventory)
write_json('data/manifest.json', manifest)
```

### 3.3 精确影像转换与验收

源解码必须是5000×5000、RGB、uint8，不把单通道建筑掩膜转换成RGB蒙混通过。记录原始地理标签，裁中央4096²，以uint16求和再 `(sum+2)//4`，不逐帧归一化、旋转、自动曝光或有损压缩。

每世界侧车记录：原始 `source_path`、文件大小与 SHA256、输出世界路径、像素 SHA256、PNG SHA256、裁剪框、降采样公式和原始地理标签。旧实现输出 `path` 会覆盖源行同名字段，本次增加独立 `source_path`，不再依赖外部反查才能恢复来源路径。

首文件通过后再全量执行；坏文件停止并记录，不能看过画面后悄悄换成更好看的瓦片。重复内容、未知波段顺序、无效像元和地理重叠分别报告。图像哈希不相同不能排除相邻位置或跨时相近重复；无坐标的数据也不能据此宣称严格无地理泄漏。

## 4. 查询与任务几何

### 4.1 公共几何

`world[cy-120:cy+120, cx-208:cx+208]`，其中中心为 origin+q。对等尺寸视口，交叠率是 `max(0,1-|dx|/416)*max(0,1-|dy|/240)`，不是 IoU。所有判定使用最终整数坐标。

每条路径记录累计路长、最大半径、最大步长、实际相邻交叠、转弯事件及 proposal_count；交叠至少0.65。核心冻结查询边界、交叠及F2/F3路长接受范围；最大半径和最大步长记录实际值，不另加未版本化的统一数值阈值。坐标检查先在原整数类型上比较边界，再转换int64，防止uint64/int64溢出绕过约束。

### 4.2 F2 / F3

F2每起点一个32新查询任务；2–4段，每段至少6步，总步数32。八方向，相邻方向转±45/90/135度；方向分量步长16/24/32，总路长1–2.5个对角线。最多10000次，失败停止，不替换固定模板。

F3按同样拓扑、基础分量8/12/16、基础路长0.60–1.25对角线构造r；large严格为2r，两变体整包验证边界与交叠，分别初始化。对角增量欧氏长度更长，不称“全路径等速”。F3是训练配方覆盖范围内的尺度响应；未见尺度必须另加训练支持范围约束和新标签。

JSON的键排序不能决定执行顺序：本次将F3显式固定small再large，避免任务保存/读取改变随机执行顺序；二者仍独立reset。

### 4.3 F5 / F7：核心随机参数

F5采用 A→B→C→D→E→end，步数16/16/32/16/16。B.x∈{448,480,512,544}、B.y=0；C.x=B.x+{-64,-32,0,32,64}、C.y∈{416,448,480,512,544}；D.x∈{-544,-512,-480,-448}、D.y∈{416,448,480,512,544}；E两轴∈{-544,-512,-480,-448}。end为B或B+(64,48)。端点间线性插值，np.rint取整。

F7共享A→B→C共32查询，后缀a：C→D→E→F→end；F=(B.x+{-32,0,32},E.y+{-32,0,32})。后缀b：C→P→Q→R→end；P.x∈{-64,0,64}、P.y∈{576,608,640,672}；Q.x∈{-672,-640,-608,-576}、Q.y∈{-64,0,64}；R.x∈{-64,0,64}、R.y∈{-672,-640,-608,-576}。每后缀4段、每段16查询。

三条路径联合接受，最多1000个候选；对命令进行D4变换，源影像和矩形视口不旋转。F5总96、F7总160唯一新输出。核心起点0/2为exact、1/3为offset，保持此定义，不自动更换正式1920包。

### 4.4 首次再入目标与调用边界

以B为中心128²世界像素目标，与I0无交集；在前32事件中每像素至少出现一次，q32完全不可见，之后每像素重新出现。保存first_event、last_prefix_visible_event、reentry_event、invisible_query_gap及fully_absent_calls。不可见间隔≥32新查询；首次/重入跨调用。

first_event是逐像素首次曝光，不统一等于第16帧B。主保持只在每像素首次重入事件评分一次；最后B图像仅是不同事件锚点的辅助结果。示例92–95重入与72–76间隔是几何事实，不是模型结果。

online16允许块内联合生成。因此这里是跨调用首次再入，不是声称第92个输出完全看不到第93–96个查询。拟议online1只能作为单独压力轨，不改变本主轨。

## 5. 本次研究审核与补充构思

### 5.1 保持不是未知质量，也不是网络记忆的充分证据

一个2048²×3的uint8画布仅12MiB。初始区域拷贝I0，其余填入固定噪声，然后严格按坐标裁剪，即可同时获得零已知、零历史、零命令交叠与零重入误差。确定性坐标函数还可能通过重算而非存图实现一致性。因此不能把低RGB误差、少缓存或少RGB字节单独解释为网络有空间理解/长期记忆。

保留这些合法反例，不强行修改指标使噪声地图在“一致性”上失败。未知分布诊断、内容条件响应和计算开销必须分开。提倡报告“表示能保证什么、生成器仍失败在哪里”，而非无条件的世界模型能力排序。

### 5.2 D4不保持矩形视口的难度

视口长宽不同，仅旋转位移不保持交叠率。例如(64,48)的整视口重叠约0.676923，90度变换后的(48,64)约0.648718。这是两次重访视口之间的重叠，不是强制要求该跳变成为相邻一步；路径仍逐步验证相邻0.65约束。

正式结果应分列方向、实际目标缺席间隔、新探索面积与可测覆盖。拒绝采样后的方向比例应报告，不假设均匀候选一定产生均匀接受分布。

### 5.3 起点绑定造成exact/offset比较混杂：新增独立配对研究

原始核心把两类重访放在不同I0位置。它可以描述两类任务表现，但不能直接把差值归因于偏移本身。

本次 `paired.py` 增加 **same-start-return-pair-v0.1**：同世界、同起点、同I0、同随机端点与朝向，对exact/offset共六条路径联合接受；每条前80查询完全相同，只有最后16查询转向不同返回端点。两者的首次曝光与前缀最后可见标签相同，各自按真实几何计算再入。F5/F7配对分别保存pair_id。

这是新增诊断，不是替换原定义。24测试世界×4起点会另增384包、49152新输出/模型/种子。建议先在dev或预注册子集跑此研究；正式全面追加必须单独列预算，不称“免费消融”。当前只用合成world_id验证几何。

偏移仍会改变最后段位移、再入事件和覆盖几何；即使配对，也应称“给定共享历史下改变返回位置的效果”，而不是隔离掉所有几何因素的纯记忆因果效应。

### 5.4 受限状态机制研究〔建议，未全部实现〕

同一真实补全骨干比较：无历史、最近帧、固定容量整帧缓存、坐标地图。分别报告缓存容量、检索候选、解码/重算开销和生成次数。另设已知像素硬保护开/关、生成历史硬保护开/关；避免把输出拼贴保证归因于网络。

若拟发展方法论文，可研究预算约束下的空间检索/分层存储，并检验质量—控制—保持—资源的可解释折中。不要只把现成地图缓存重新命名为新架构。更大的空间范围或严格记忆预算只能作为版本化研究变量，不能暗改紧凑主轨制造优势。

## 6. 评价、日志与独立回放

### 6.1 四类RGB指标的含义

K=A_t∩O：对I0；P=(A_t∩U)\O：对该像素首次计划曝光时的有效公开值；N=A_t\(U∪O)：首次未知。坐标对应固定，不通过最优平移/旋转消除控制错误。所有RGB MAE归一化到[0,1]，计划面积、有效面积、完整率并列。

首次输出失败也写入seen与first_event，但不生成有效reference；后续成功永远不能补回这个首次参考。缺失不是结构性不适用：空交集可为not_applicable，计划需评分但无输出为missing；零覆盖时误差null。

F7前缀只计一次，分支分别锚定共同前缀首次值；仅当两支目标有效覆盖均100%才给paired_reentry_mae。两个分支彼此相似不能替代对共同历史的保持。

### 6.2 独立PNG回放〔本次实现〕

每次run保存 evaluator 私有的task.json、initial.png、events.jsonl、各流PNG与summary.json。会话含journal_schema、task_sha256和I0像素哈希。F7目录为prefix/a/b，prefix仅32输出；其余任务按固定流名。

`replay.py`按冻结任务重新计算标签，验证请求/响应/输出顺序和坐标、日志链、PNG模式/大小/像素哈希、缺失槽位、未记账PNG，并重建独立Ledger与F7前缀分叉后比较summary。它拒绝重复JSON键、NaN/Infinity和明显路径/软链接逃逸。

```bash
python -m rswm_inria.cli demo --model oracle --save-images --out runs/oracle-new
python -m rswm_inria.replay --run-dir runs/oracle-new/synthetic-demo-o0-F5 --out runs/oracle-new/f5-recomputed.json
```

既有旧日志不含新schema、task绑定和I0文件，不能无提示地认证为新格式；应重新运行或显式迁移并记录迁移边界。

**信任边界：**任意人可重写内容并重新计算无密钥哈希链。`--expected-head`只有来自独立保存的可信记录时才用于检测整链替换。回放验证内部一致性，不证明真实提交时间、隐藏信息不可达、GPU成本、模型随机状态或共享可写缓存不存在。公开评测需要隔离评测进程/模型进程、禁网或白名单、只暴露当前调用和独立保存收据；当前未实现安全沙箱。

### 6.3 运动测量〔已有工程，尚未校准认证〕

图像仪器不能接收期望命令来寻找“正确答案”。从图像内容平移得到视口位移，再与命令比较。以calibration真裁剪及可控反向/缩幅/放幅、低对比、重复纹理等校准；metric_validation不能再调参数。可信估计、歧义、证据不足、提交失败分列；报告可信覆盖和条件误差，不丢弃难图后只报均值。

连通到初始锚的有效边链才计算路径/终点误差，断链不以真坐标重锚；F3路长比只有双方均满足可测条件才给值，并保留配对分母。低纹理水域不可仅因配准困难而被源筛选删除。

### 6.4 未知质量〔部分工具已有，正式指标待冻结〕

按计划未知覆盖预选固定128²世界图块，不按模型画面择优；从跨事件首次有效提交拼出每块，每像素一次。未完整覆盖的块不由后续生成补写，报告计划块、完整块、缺失像素；分布比较需要同一冻结采样规则下的留出实景与真实—真实参照。

现有polynomial MMD-U函数不是已认证的标准Inception-KID。先冻结特征骨干、权重revision、预处理、统计单位、子集大小和随机种子，再命名具体指标。无偏估计可出现负值，不为美化结果截断。不同方法完整块集合不同，应同时给匹配计划子集和覆盖，不能靠少提交困难块改善分数。

分布距离不证明条件正确、道路拓扑合理或每个地物语义真实。条件干预A只表示输出敏感性，局部规则C只表示候选规则支持，均不能合成“整体语义质量”。

### 7.1 第二来源的最小可行设计〔建议〕

## 8. 强基线与公平适配

| 方法 | 最低验收要求 | 不允许的替代说法 |
|---|---|---|
| 无数值I2V，如Wan接口 | 真实权重、固定prompt/seed/适配尺寸；原生额外帧计成本；说明未消费数值q | 不能把自然语言“向右”包装为精确坐标模型 |
| 数值条件生成 | 实际注入q/delta_q/固定单位条件；训练与测试原点一致；真实训练和自主闭环推理 | 仅输出裁剪或伪造镜头轨迹不等于训练了数值视频模型 |
| Eager整图 | I0条件下真实补全有限世界，全部预生成区域计成本，再按q裁剪 | Oracle裁剪或固定噪声不是实际生成基线 |
| Lazy增量地图 | 同一补全器、同一窗口与采样设置；仅用I0及自主历史填未知 | 真历史teacher forcing结果不能冒充测试闭环 |
| Genesis/RemoteBAGEL | 按原生操作和权重实现专用适配，禁用真实底图联网获取，说明超出原训练分布的转换 | 通用Diffusers接口不是已复现这些系统 |
| Copy/Random/Noisemap/Oracle | 作为仪器反例/正对照，明确额外信息权限 | 不进入实际生成模型的质量胜负结论 |

同骨干地图比较保持512×512上下文、256×256核心填充，避免整图先缩到512却让增量用局部512的有效分辨率混杂。固定权重校验、scheduler、步数、精度、输入输出转换；模型加载和动态状态可分别计量。

现有通用补全和Wan适配器只有模拟管线测试，真实检查点实验与数值条件训练尚未完成。现有Eager/Lazy实现仍可分配完整RGB画布，不能称为稀疏存储系统。

## 9. 实验矩阵、统计和成本

### 9.1 最低主实验矩阵

E1：真实方法×F2/F3，方向/幅度/转弯、坐标交叠、已知保持、运动可信覆盖。

E2：真实方法×F5/F7，目标首次再入与共同前缀保持；exact/offset分列；按实际间隔、完整缺席调用数、新探索面积解释难度。

E3：同补全骨干Eager/Lazy及历史组织消融；未知质量、初始化、生成窗口数、状态和时间均报告。

E4：新增same-start-return-pair，配对比较，不把不同origin的核心差值当作无混杂效应。

E5：固定对角线单位与逐轨迹归一化消融。后者必须披露离线未来范围依赖；在线不能偷看未来再计算归一化。

E6：两个测试城市分别出表，加一独立来源；zero-shot与源适配分别标识。

每个实验预注册主要比较、种子、失败规则和统计单位。不要根据测试结果反复调整指标或只展示成功轨迹。

### 9.2 统计单位与覆盖

任务/起点/种子先按世界聚合，世界再在各城市聚合；主表San Francisco和Innsbruck分列，然后等城市权重均值。两地不是地理总体的大样本，不能以对两城市bootstrap给“全球泛化置信区间”。可报告在固定两城市条件下按源世界重采样的区间，并明确瓦片空间邻接仍可能相关；有坐标后应提升到更合理的地理组。

所有配对一起重采样，保留两个方法都失败的任务。条件MAE同时报告计划分母、有效覆盖和完整率；不同方法可测子集不同，需要匹配子集敏感性表。缺某城市数据时不能把其权重偷偷分给另一个城市。

### 9.3 核心规模与资源预算

核心120世界×4起点×4族=1920包；测试24世界=384包。每起点32+64+96+160=352唯一新输出，测试每模型每种子33792张；三种子101376张、原始RGB **30,364,139,520 bytes（约30.36GB/28.28GiB）**。这是规范输出，不含视频原生额外帧、快照、日志、临时缓存和权重。

120张2048²RGB世界原始像素约1.51GB，PNG实际大小取决于图像。源TIFF临时估计约9GB，以正式manifest总字节替换。四个起点高度相关，不提高城市独立性。

训练60世界×(32F2+16F3对)=3840个33视图clips，共126720真实视图事件；只存坐标，按batch裁剪。训练teacher forcing和测试自主历史严格分开。

附加同起点全测试研究另有49152新输出/种子；优先跑预注册小规模，不把它计入33792核心数字。GPU预算先由dev预跑测得：记录真实每块/窗口耗时、额外帧、失败重试规则，再外推总时，不凭空报某型号GPU小时数。

资源字段分离：加载、初始化、每调用生成、输出转换/IO、快照恢复、GPU同步时间、显存峰值、进程RSS、动态缓存与磁盘。测不到填null不是0；RGB数组大小不是进程内存，CPU墙钟也不是GPU同步计算时间。
